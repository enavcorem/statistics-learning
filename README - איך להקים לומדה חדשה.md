# איך להקים לומדה חדשה על אותו מנוע

הלומדה הזו (XLOOKUP) ולומדת הסטטיסטיקה רצות על **אותו מנוע בדיוק**. המסמך הזה
מסביר איך להקים את הלומדה הבאה בלי לכתוב שורת קוד אחת של מנוע.

---

## הכלל היחיד שחשוב

> **`js/` ו-`css/` הם המנוע. לא נוגעים בהם בתוך קורס.**
> כל מה שייחודי לקורס יושב ב-`content/`.

למה זה חשוב: כשיהיו לך ארבע-חמש לומדות, תיקון באג במנוע צריך להגיע לכולן.
אם כל קורס "שיפץ" את המנוע קצת, אי אפשר יותר להחליף אותו. כל עוד הכלל נשמר,
שדרוג קורס = להעתיק לתוכו את `js/` ו-`css/` מהגרסה העדכנית, וזהו.

---

## מה יש בכל תיקייה

| תיקייה | מה זה | לגעת? |
|---|---|---|
| `js/` | המנוע: ניתוב, התקדמות, נעילה, רינדור, מבחנים | ❌ |

## שישה צעדים להקמת קורס חדש

### 1. להעתיק את התיקייה
העתיקי את `xlookup-learning` בשלמותה, ושני את השם (למשל `pivot-learning`).
מחקי מתוכה את `content/ch1` … `content/ch5`.

### 2. לעדכן את `content/manifest.js`
זה **מקור האמת היחיד** למבנה הקורס. שלושה דברים בראש הקובץ:

```js
export const COURSE_ID = 'pivot';   // חייב להיות ייחודי! ממנו נגזרים מפתחות האחסון

export const COURSE = {
  title: 'לומדת טבלאות ציר',
  icon: '📊',
  welcome: { f: 'ברוכה הבאה ללומדת טבלאות ציר! 📊', m: 'ברוך הבא…' },
  finaleText: 'סיימת את כל יחידות הלומדה 📊',
  teacherTitle: '📊 לוח מורה — לומדת טבלאות ציר',
};
```

ואז רשימת `CHAPTERS` — פרקים, ובכל פרק `units`. לכל יחידה:

```js
{ id: 'pv-ch1-u1', title: 'מה זו טבלת ציר', type: 'lesson',
  icon: '🔍', estMinutes: 6, modulePath: 'ch1/ch1-u1-intro.js' }
```

- **`id`** — חייב להתחיל בקידומת ייחודית לקורס (`pv-`). כל הלומדות חולקות
  פרויקט Supabase אחד, והקידומת היא מה שמונע התנגשות.
- **`type`** — `lesson` / `lab` / `quiz` / `reference` / `bonus` / `exemption`.
  `bonus` ו-`exemption` **לא** נספרים לנעילה ול-XP.
- **`estMinutes`** — מוצג לתלמידה, ועוזר לך לתכנן מנות.

### 3. לכתוב את קבצי התוכן
כל יחידה היא קובץ אחד תחת `content/chX/`, במבנה הזה:

```js
export default {
  title: 'שם היחידה',
  slides: [
    {
      blocks: [ /* מה מציגים */ ],
      question: { /* שאלה אחת, רשות */ },
    },
  ],
};
```

מבחן נראה אחרת — `questions` במקום `slides`, ועם `passMark`:

```js
export default {
  title: 'מבחן פרק',
  passMark: 70,
  questions: [ { type: 'mc', topic: 'נושא', prompt: '…', options: [...], explanation: '…' } ],
};
```

`topic` על כל שאלת מבחן מזין את דוח "נושאים לחיזוק" ואת לוח המורה — שווה
להשקיע בניסוח שלו.

### 4. בלוקים וסוגי שאלות זמינים

**מהמנוע (תמיד זמינים):**
`text` · `concept` · `example` · `trap` · `table` · `chart-bar` · `box-plot` · `video`

**סוגי שאלה מהמנוע:** `mc` · `numeric` · `match`
(`match` עובד בשיעור בלבד, לא במבחן.)

**מהקורס הזה** (ב-`content/widgets/`, אפשר להעתיק או למחוק):
`xlookup-demo` · `formula` · `two-tables` · `timeline` · `compare` · `error-demo`,
וסוג השאלה `formula-parts`.

### 5. `content/widgets/index.js` — חובה שיהיה, גם אם ריק
המנוע מייבא את הקובץ הזה תמיד. אם לקורס החדש אין בלוקים משלו, השאירי אותו
עם הערה בלבד. אם כן — רושמים כך:

```js
import { registerBlockRenderer } from '../../js/engine/blocks.js';
import { registerQuestionType } from '../../js/engine/question-types.js';

registerBlockRenderer('my-block', renderMyBlock);
registerQuestionType('my-question', { practice: fn, exam: fn });
```

> סוג שאלה שנרשם ל-`practice` בלבד יציג אזהרה גלויה אם ישימו אותו במבחן.
> זה בכוונה — עדיף אזהרה מאשר ניקוד שגוי בשקט.

**צבעים:** אין להוסיף צבעים "חד-פעמיים" בתוך רכיבים. טוקנים של הקורס מוגדרים
בראש קובץ ה-CSS שב-`content/widgets/`, על `:root`.

### 6. לבדוק ולהריץ

```bash
node tools/validate-content.mjs
```

בודק שכל הקבצים נטענים, שכל סוג בלוק/שאלה מוכר, ושלכל שאלה יש בדיוק תשובה
נכונה אחת. **להריץ אחרי כל שינוי תוכן** — זה תופס בשנייה את מה שאחרת מתגלה
רק כשתלמידה נתקעת באמצע יחידה.

הבדיקה גנרית: היא לא מחזיקה רשימת סוגים משלה אלא **שואלת את המנוע** מה רשום
אצלו (`getBlockTypes()` / `getQuestionTypes()`), אחרי שהיא טוענת את
`content/widgets/index.js` של הקורס. לכן היא עובדת כמו שהיא בכל לומדה חדשה,
בלי לגעת בה. (`tools/https-stub.mjs` הוא עזר טכני קטן שמנטרל את הייבוא מ-CDN
בזמן הבדיקה — node לא יודע לטעון `https://`, דפדפן כן.)

להרצה מקומית (הלומדה משתמשת ב-ES modules ולכן חייבת שרת, לא פתיחת קובץ):

```bash
node ../.claude/dev-server.mjs
```

## שני דברים שכדאי לדעת

### מצב כיתה — לשיעור פרונטלי

**תכונה בהצטרפות מרצון. היא כבויה אלא אם הקורס ביקש אותה במפורש:**

```js
export const COURSE = { /* … */ classMode: true };
```

בקורס שביקש, הוספת `?class=1` לכתובת פותחת את **כל** היחידות במכשיר הזה
ומסתירה את מונה ה-XP. זה נשמר במכשיר, כך שמספיק פעם אחת על מחשב המורה.
לכיבוי: `?class=0`.

הקישור לתלמידות הוא הרגיל, בלי הפרמטר — אצלן הנעילה נשארת פעילה.

**בקורס שלא ביקש — `?class=1` לא עושה כלום**, ו-`canAccessUnit` מתנהגת בדיוק
כמו לפני שהתכונה נוספה. כך אפשר להחזיק אותה במנוע המשותף בלי לגעת בקורס
שבו הנעילה ההדרגתית היא עיקר הפדגוגיה (לומדת הסטטיסטיקה, למשל, לא
מפעילה אותה).

### Supabase
**אין צורך להריץ שום דבר לקורס חדש.** כל הלומדות חולקות פרויקט אחד ואותה
טבלת `students` — כלומר תלמידה שכבר נכנסה ללומדה אחת מזוהה גם בשנייה.
ההפרדה בין הקורסים היא דרך קידומת ה-`id` של היחידות, ולוח המורה של כל קורס
מסנן אוטומטית את מה שלא שייך לו.

`supabase/schema.sql` נשמר לתיעוד בלבד — הוא כבר רץ.
